# SMB 子目录读取阻塞隔离

## 问题与判断

用户报告启动后 SMB 根目录能打开，进入子目录一直等待，随后所有 Web 页面无响应。原目录列表在 Web 进程直接调用 Directory.Exists、目录枚举和文件属性读取；这些调用没有可靠的 CIFS 内核等待取消机制。应用阻塞机制有源码依据，首次挂载失效的底层原因尚未确定。

## 本次修复

- Linux 上已配置 SMB 的根目录和子路径，目录列表改为独立 GNU find 进程，枚举和属性读取均发生在子进程内；不先调用 Directory.Exists。
- 单次预算 5 秒；全局并发 3，同挂载并发 1，繁忙立即返回 503，读取失败或超时返回 504。
- 输出最多 4 MiB 字符；超限失败，不返回不完整目录列表。
- 超时尝试结束进程，并记录尚未退出的 PID；同挂载存在未退出操作时不继续创建读取进程。
- 子路径故障关联到所属挂载，触发即时检查；保留状态机已有等待重试、人工处理和恢复规则。
- 启动状态机未登记时，读取配置识别 SMB 路径，避免首次请求落回进程内访问。
- 日志包含请求 ID、根路径、访问路径、PID、开始/结束、耗时、退出码、错误摘要、超时后是否仍存活。日志可能包含目录名，请按现有管理员日志权限访问。
- Docker 安装 findutils。原生 Linux 部署需要 GNU find（通常由 findutils 提供）；缺失时返回错误，不降级为进程内读取。

## 范围和限制

仅隔离目录列表，文件读取、上传、写入、删除等接口仍需后续逐项隔离。路径别名、符号链接映射到 SMB 但不位于配置路径下的访问不在本次识别范围。

GNU find 一次完成条目和属性读取，日志不能精确区分内核阻塞在 readdir 还是单个 stat。需结合 PID、内核 CIFS 日志进一步定位。健康检查仍是根目录探测，关联子目录错误不等于已验证子目录恢复。
