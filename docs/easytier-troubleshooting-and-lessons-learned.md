## 一、问题一：节点始终处于「虚拟 IP: DHCP 分配中...」

### 1.1 故障现象

用户创建并启动 EasyTier 节点后，节点显示处于运行中状态，但虚拟 IP 始终未分配，界面持续停留在 `虚拟 IP: DHCP 分配中...`，且无法与虚拟局域网内的其他设备通信。

用户节点的原始 TOML 配置如下：
```toml
# Generated by LinuxWebTool EasyTier Manager at 2026-10-07 11:33:04 UTC
inst_name = "node_76"
network_name = "fnnas"
network_secret = "fnnas.hkadmin"
dhcp = true
no_listener = true
peers = ["wss://p.333123.xyz"]
```

### 1.2 底层原因剖析

该问题由**两个维度的根因**叠加导致：

#### 根因 1：EasyTier 2.x TOML 语法规范不匹配，导致节点成为孤岛
* **对端语法不识别**：EasyTier 2.x 的 TOML 解析器针对 Peer 采用了表数组（Table-Array）结构 `[[peer]] uri = "..."`。旧代码生成的 `peers = ["..."]` 字符串数组在 Rust 强类型反序列化时被完全忽略，导致内核的 Connector 列表为空（0 个对端连接）。
* **网络标识未置于子表**：EasyTier 2.x 的网络凭据必须位于 `[network_identity]` 子表中。写在顶层时，内核回退使用 `default` 网络名。
* **去中心化 DHCP 握手机制**：EasyTier 并不存在单机本地 DHCP 服务。当启用 DHCP（`dhcp = true` 且未指定静态 `ipv4`）时，节点必须先接入对端集群，通过网络内部对等协商获得可用网段与空闲 IP。当节点处于“孤立无连接”状态时，DHCP 握手永远无法推进。

#### 根因 2：Windows 非管理员权限导致 WinTun 虚拟网卡创建失败
EasyTier 默认调用 `wintun.dll` 在操作系统中创建名为 `EasyTier` 的虚拟以太网卡适配器。在 Windows 系统上，调用 `WintunCreateAdapter` 安装网络设备驱动属于特权操作。
当 WebHost 服务以普通用户权限运行（`IsAdministrator = False`）时，内核会输出以下错误：
```text
WARN CORE: Failed to add Easytier to firewall allowlist, error=拒绝访问。 (0x80070005)
ERROR CORE::INSTANCE: tun device error err=rust tun error Failed to create adapter
```
内核每隔数秒重试创建适配器，网络接口初始化挂起，无法将虚拟 IP 绑定给本地物理网卡。

### 1.3 解决方案与落地代码

#### 1. 规范化配置生成器（兼容新老版本）
在 `LinuxWebTool.Infrastructure.EasyTier.EasyTierConfigGenerator` 中重构生成逻辑：
```csharp
// 1. 网络标识独立表输出
sb.AppendLine("[network_identity]");
sb.AppendLine($"network_name = \"{EscapeTomlString(entity.NetworkName)}\"");
sb.AppendLine($"network_secret = \"{EscapeTomlString(entity.NetworkSecret ?? "")}\"");
sb.AppendLine();

// 2. 对端列表生成 [[peer]] 表数组与兼容 peers 字段
var peers = DeserializeList(entity.PeersJson);
if (peers.Count > 0)
{
    sb.AppendLine($"peers = [{string.Join(", ", peers.Select(p => $"\"{EscapeTomlString(p)}\""))}]");
    foreach (var p in peers)
    {
        sb.AppendLine();
        sb.AppendLine("[[peer]]");
        sb.AppendLine($"uri = \"{EscapeTomlString(p)}\"");
    }
}
```

#### 2. 标准 TOML 输出效果
更新后的配置文件规范格式如下：
```toml
inst_name = "node_76"
network_name = "fnnas"
network_secret = "fnnas.hkadmin"
dhcp = true

[network_identity]
network_name = "fnnas"
network_secret = "fnnas.hkadmin"

no_listener = true
peers = ["wss://p.333123.xyz"]

[[peer]]
uri = "wss://p.333123.xyz"
```
实测该配置生效后，内核立即建立 WSS 连接并拉取到对端拓扑。

## 二、问题二：跨平台权限限制（Windows 管理员与 Linux Root / CAP_NET_ADMIN）

### 2.1 故障现象与报错信息

* **Windows 平台**：
  以普通用户双击运行或在非提升权限终端启动程序时，内核日志频繁报错：
  `Failed to create adapter (拒绝访问 0x80070005)`。
* **Linux 平台**：
  以普通用户（非 root）直接启动时，打开 TUN 设备失败：
  `Failed to open /dev/net/tun: Permission denied` 或 `Operation not permitted (os error 1)`。

### 2.2 跨平台特权模型差异分析

| 操作系统 | 底层驱动/接口 | 权限要求 | 报错信息 | 解决方案 |
| :--- | :--- | :--- | :--- | :--- |
| **Windows** | `wintun.dll` / `WinDivert64.sys` | **管理员权限 (Administrator)** | `Failed to create adapter (0x80070005)` | 1. 鼠标右键“以管理员身份运行”启动 WebHost<br>2. 注册为 Windows 服务并以 LocalSystem/管理员账户运行<br>3. 无网卡纯中继场景配置 `--no-tun` |
| **Linux** | `/dev/net/tun` 内核设备 | **Root 用户** 或 **`CAP_NET_ADMIN`** 能力 | `Failed to open /dev/net/tun: Permission denied` | 1. 使用 `sudo` 或 root 启动<br>2. 精细化授权：`sudo setcap cap_net_admin=+ep easytier-core`<br>3. systemd 服务配置 `AmbientCapabilities=CAP_NET_ADMIN`<br>4. Docker 容器参数 `--cap-add=NET_ADMIN --device=/dev/net/tun` |

### 2.3 三层全链路权限感知与告警方案

为了避免用户在缺乏权限时盲目排查，系统在全栈实现了三层主动感知与预警：

#### 第一层：全局进程特权状态探测
在 `EasyTierHostSupervisor.cs` 中实现运行时跨平台探针：
```csharp
public static bool CheckProcessElevation(out string? warning)
{
    if (OperatingSystem.IsWindows())
    {
        try
        {
            using var identity = System.Security.Principal.WindowsIdentity.GetCurrent();
            var principal = new System.Security.Principal.WindowsPrincipal(identity);
            var isAdmin = principal.IsInRole(System.Security.Principal.WindowsBuiltInRole.Administrator);
            if (!isAdmin)
            {
                warning = "当前 WebHost 服务以普通用户权限运行。在 Windows 上创建 TUN 虚拟网卡需要管理员权限，请通过“以管理员身份运行”启动程序，避免出现网卡创建失败或 DHCP 无法生效的问题。";
                return false;
            }
        }
        catch { }
        warning = null;
        return true;
    }

    if (OperatingSystem.IsLinux())
    {
        var isRoot = Environment.UserName == "root" || Environment.GetEnvironmentVariable("USER") == "root";
        if (!isRoot)
        {
            warning = "当前未以 root 权限运行。在 Linux 下创建 TUN 虚拟网卡需要 root 权限，或执行 'sudo setcap cap_net_admin=+ep <easytier-core路径>' 赋予网卡管理能力。";
            return false;
        }
        warning = null;
        return true;
    }

    warning = null;
    return true;
}
```

#### 第二层：Web 控制台顶部预警横幅
当 `engineStatus.hasAdminPrivilege == false` 时，页面核心指标栏下方自动渲染暖黄色告警条：
```html
<div v-if="engineStatus && !engineStatus.hasAdminPrivilege" class="p-3 rounded-lg bg-amber-950/40 border border-amber-500/50 flex items-start gap-3 text-xs text-amber-200">
  <span class="text-base leading-none">⚠️</span>
  <div class="flex-1">
    <div class="font-bold text-amber-300 mb-0.5">系统运行权限提示：未获得管理员/特权身份</div>
    <div class="text-amber-200/90 leading-relaxed">{{ engineStatus.privilegeWarning }}</div>
  </div>
</div>
```

#### 第三层：节点卡片运行期精准错误捕获
在 `EasyTierNodeManager.cs` 中异步接管子进程标准错误流，正则捕获 `Failed to create adapter`：
```csharp
if (e.Data.Contains("Failed to create adapter", StringComparison.OrdinalIgnoreCase))
{
    runtimeState.LastError = OperatingSystem.IsWindows()
        ? "创建 TUN 虚拟网卡失败 (Windows 下创建虚拟网卡需要以管理员身份运行 WebHost)"
        : "创建 TUN 虚拟网卡失败 (Linux 下需要 root 或 CAP_NET_ADMIN 权限)";
}
```
前端节点卡片立即弹出醒目的红色提示条，虚拟 IP 状态由“DHCP 分配中...”自动切换为“待就绪 (见下方提示)”。

## 三、问题三：对端拓扑表格未展示「虚拟 IP」与实际网络指标

### 3.1 故障现象

在节点抽屉中展开“在线对端拓扑”表格时，表格仅展示了“节点 ID、链路类型、传输协议、物理对端地址、往返时延、累计流量”，**缺少了每个对端分配的「虚拟 IP」列**，且时延与流量均显示为 `< 1 ms` / `0 B / 0 B`。

### 3.2 原因剖析

1. **前端表格列遗漏**：`EasyTierView.js` 的对端表格头中未包含 `<th>虚拟 IP</th>`，表格数据行未渲染 `p.virtualIpv4`。
2. **CLI JSON 数据未完整解析**：EasyTier CLI 的 `easytier-cli peer` 命令返回格式如下：
   ```json
   {
     "cidr": "10.126.126.1/24",
     "ipv4": "10.126.126.1",
     "hostname": "R77435",
     "cost": "p2p",
     "lat_ms": "0.25",
     "loss_rate": "0.0%",
     "rx_bytes": "10.83 kB",
     "tx_bytes": "17.00 kB",
     "tunnel_proto": "tcp,tcp6",
     "nat_type": "PortRestricted"
   }
   ```
   后端代码在反序列化该数据时，`lat_ms`、`rx_bytes`、`tx_bytes` 字段未作字符串解析，直接赋予了默认值 0。

### 3.3 解决方案

1. **后端增强**：在 `EasyTierNodeManager.cs` 中实现 `ParseByteString`，安全将 `10.83 kB` 等单位字符串转换为字节整数，并解析浮点数时延；同时将 CLI `route` 输出的路由表统一注入明细 DTO。
2. **前端重构**：
   * 表格表头显式加入 **「虚拟 IP」** 列，以高亮翠绿徽章展示每个对端的网段 IP（如 `10.126.126.1/24`），本机节点与中继节点分别予以针对性标识；
   * 第一列升级为“主机名 + 底层 Peer ID”双行呈现；
   * 表格下方追加展示 **「虚拟网段路由表」**，直观展示目标网段、下一跳、跃点数和路径延时。

## 四、问题四：本地监听端口配置后仍使用默认端口（AOT 序列化陷阱）

### 4.1 故障现象

在创建节点时填入了自定义监听端口（例如 `["tcp://0.0.0.0:11010", "udp://0.0.0.0:11010"]`），但保存并启动后，节点实际监听依然使用了内置默认端口。

### 4.2 原因剖析

本项目开启了 .NET 10 的 Native AOT 反射拦截开关：
```xml
<JsonSerializerIsReflectionEnabledByDefault>false</JsonSerializerIsReflectionEnabledByDefault>
```
在旧代码中，针对 `Listeners`、`Peers`、`Routes` 等集合使用了无源生成上下文的通用调用：
```csharp
// ❌ 触发 AOT 运行时反射异常并被 catch 吞掉，导致集合被回退为空列表 []
JsonSerializer.Deserialize<List<string>>(json)
```
因为反序列化失败，默认回退为空列表，配置生成器判定无监听地址时，自动生成了回退默认值，造成用户自定义端口失效。

### 4.3 解决方案与架构门禁 LinuxArch018

1. **注册源生成上下文**：
   在 `EasyTierJsonContext.cs` 中显式注册集合类型：
   ```csharp
   [JsonSerializable(typeof(List<string>))]
   [JsonSerializable(typeof(string[]))]
   internal partial class EasyTierJsonContext : JsonSerializerContext { }
   ```
   所有集合反序列化统一走强类型上下文：
   ```csharp
   JsonSerializer.Deserialize(json, EasyTierJsonContext.Default.ListString)
   ```
2. **建立自动化架构门禁 `LinuxArch018`**：
   在 `LinuxWebTool.ArchitectureTests` 中建立静态反射调用拦截门禁：
   * 扫描 `LinuxWebTool.Infrastructure` 与 `LinuxWebTool.WebHost` 下的所有 C# 源文件；
   * 严禁出现未传入 `JsonTypeInfo` 或 `JsonSerializerContext` 的泛型 `JsonSerializer.Serialize` / `JsonSerializer.Deserialize` 调用；
   * CI 与本地 `./scripts/verify-fast.ps1` 自动执行该门禁，一旦出现反射反序列化立即阻断构建。

## 五、最佳操作实践总结

1. **Windows 部署规范**：
   * 需创建 TUN 虚拟网卡时，始终**以管理员身份运行** WebHost 服务；
   * 若作为开机自启后台服务，建议使用 Windows Service（LocalSystem 权限）运行。
2. **Linux 部署规范**：
   * 生产环境建议通过 systemd 运行，配置 `AmbientCapabilities=CAP_NET_ADMIN`；
   * 非 root 部署时执行一次赋权：`sudo setcap cap_net_admin=+ep /path/to/easytier-core`。
3. **节点组网排错标准流程**：
   * ① **看顶部横幅**：是否有“未获得管理员身份”预警；
   * ② **看对端数量**：若对端数为 0，检查 Peer 节点地址是否可达（防火墙、域名解析、中继状态）；
   * ③ **看节点报错**：若出现 `创建 TUN 虚拟网卡失败`，立即提升服务运行权限；
   * ④ **看拓扑明细**：展开抽屉查看虚拟 IP、链路协议（Direct P2P / Relay）与延时指标。
