# EasyTier 多节点故障隔离与防回归方案

日期：2026-10-10。

## 目标与边界

同机多个节点使用重叠虚拟网段时，在调用引擎前拒绝启动；重复启动不能遗失旧进程；改名必须停止旧实例；原生调用不能无限占用 HTTP 工作线程；前端刷新不能累积。此前两节点同开导致失联的具体现场机制仍需路由和线程证据，本次修复覆盖已经确认的代码缺口。

## 实施步骤

- [x] 添加真实行为回归测试及现有问题的失败证据。
- [x] 新建 `EasyTierNetworkGuard`：解析实际 TOML 顶层虚拟 IPv4，与当前运行节点和本机非 EasyTier IPv4 网段比较；未知 DHCP 地址不允许与其他运行虚拟节点混用，避免无法验证冲突。原始 TOML 的字面 IPv4 及引用键名同样检查，转义键名拒绝执行。
- [x] 在 `EasyTierNodeManager` 中串行处理创建、更新、删除、启动、停止和升级；重复启动返回已有运行结果，使用旧运行名称停止重命名节点，失败停止保留运行记录。
- [x] 添加原生调用执行边界：独立线程、有限等待、单个在途调用；超时期间拒绝新调用，避免线程及任务累积。未完成的原生启动保留节点占位，避免错误重试。
- [x] 前端每轮刷新采用单次在途保护，节点及引擎查询开启请求超时并保证忙碌状态恢复。
- [x] 将行为测试接入既有后端架构测试和前端门禁；保留原基线，不扩充豁免。
- [x] 运行相关后端/前端测试、构建、门禁和局部 lint；记录实际结果及生产验证边界。

## 重点验证

重复网段及 `/16`、`/24` 包含关系；不同网段通过；裸 IP 默认 `/24`；Raw TOML 覆盖；DHCP 未知网段；两个并发启动；原生永久等待不会反复创建线程；请求取消不能取消已经开始的原生操作；停止失败保留状态；改名使用旧名称；前端重叠轮询和失败后恢复。

## 风险和现场处理

禁止冲突启动属于预期行为变化，报错必须指出冲突来源。原生调用超时不能强制杀死线程或内核操作，未确认完成前禁止新操作；CoreBinary 进程保持可管理。动态 DHCP 或外部路由在运行中发生变化，应用无法只凭静态配置保证绝对安全。Windows 测试不执行生产 TUN/路由操作；上线后仍须比较实际路由及服务器本机 HTTP 响应。

## 最终实现和验证记录

- 生命周期互斥等待预算 5 秒；原生启动 5 秒、停止/补丁 3 秒、状态采集 2 秒。状态快照正常缓存 3 秒；调用未完成时复用旧快照，不追加工作线程。超时后的工作必须实际返回才能释放槽位，原生异常会被观察。
- 两个静态 `10.126.126.x/24` 节点的第二次启动会明确报网段重叠；更新运行节点时也在写入配置、停止旧实例前检查，冲突配置不覆盖现有运行设置。裸 IPv4 按 EasyTier 的默认 `/24` 检查，本机网段使用实际接口掩码。
- 单节点 DHCP 仍可启动；其协商结果无法在启动前获知，因此不能保证与 LAN 无冲突。含未知 DHCP 的多节点组合要求用户改用明确且不重叠的静态地址；本次不实现运行期自动换址。
- 自动启动和升级恢复复用同一启动检查。RPC 端口从本应用运行记录中分配未占用端口，避免原先名称 hash 碰撞；不保证避开其他外部程序的监听端口。
- 初始失败证据：网段门禁缺失导致 6 项测试失败；原前端一次启动加两次轮询产生 3 次未完成查询，预期应为 1 次。修复后的行为回归通过。
- 全部后端架构测试 157 项通过；EasyTier 原有功能及生命周期集成测试 10 项通过。集成测试模拟原生采集阻塞，验证第二次查询不增加调用且登录 HTTP 200，未运行真实 TUN 引擎。
- 前端静态及行为门禁通过，新增 `FE-EASYTIER-REFRESH` 不允许基线豁免；局部 ESLint 通过。Release 解决方案构建通过，0 警告、0 错误。
- 新增 `LinuxArch020/021/022` 测试与规则说明纳入既有 CI 的架构/接口测试，无需额外工作流。没有执行 Git 提交、推送或生产部署。
