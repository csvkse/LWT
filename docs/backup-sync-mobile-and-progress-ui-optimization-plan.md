# 备份与同步模块：实时进度交互美化与移动端响应式架构优化方案

## 1. 背景与现状问题分析

在当前 LinuxWebTool 的「文件夹备份与同步」视图中，虽然已成功接入无锁实时执行进度追踪与 1 秒轮询机制，但在 UI 布局与移动端体验上仍存在明显缺陷：

### 1.1 桌面端表格排版被大卡片撑破与状态重复
- **列宽挤压失衡**：进度面板直接作为一个块级元素内嵌在第一列「任务名称」的 `<td>` 内部，且设置了 `min-w-[20rem]`。当任务处于运行态时，第一列被大幅撑宽，导致「路径」、「策略」、「上次同步」与「操作」列被挤压变形。
- **状态信息割裂与冗余换行**：在同一行中，左侧进度面板显示了详细的阶段描述（如 `正在镜像复制变动数据...`），而右侧的「上次同步」单元格内又渲染了一个带脉冲动画的长文本徽标，在狭窄的单元格中被动折行为 3 行（`⚡ 正在镜像 / 复制变动数 / 据...`），破坏了表格对齐与视觉秩序。

### 1.2 移动端（窄屏设备）缺乏自适应，出现横向长滚动
- 当前任务列表硬编码了 `<table class="data-table min-w-[52rem]">`，外层包裹 `panel overflow-x-auto`。
- 在宽度为 375px ~ 768px 的手机或竖屏平板上，用户必须手动左右横划屏幕才能查看到任务状态、调度时间或点击「立即同步 / 终止任务」，交互断层严重，触控区域偏小易误触。

## 2. 业界主流设计与优秀方案借鉴

| 工业级产品 / 方案 | 桌面端表格做法 | 移动端（Narrow Viewport）做法 | 核心亮点 |
| :--- | :--- | :--- | :--- |
| **群晖 Synology DSM (Hyper Backup / Active Backup)** | 列表主行展示紧凑状态徽章与微型进度条，可下拉/展开副行查看详细字节与文件流 | 自动降级为流式卡片，进度条横贯整个卡片，单手触控操作条置底 | 层次分明，表格列宽永远固定不形变 |
| **Vercel / GitHub Actions** | 运行状态通过紧凑状态点（Pill）与时间显示，点击展开详细步骤抽屉 | 列表卡片化，带渐变呼吸光晕，状态一目了然 | 现代化高反差暗黑科技美学，大触控热区 |
| **Rclone WebUI / Cloudreve** | 双进度仪表盘（文件数比率 + 字节传输量），动态速率曲线与 ETA | 纵向堆叠卡片，路径以分级图标清晰标识 | 强遥测指标展示，零误触 |

## 3. 设计模式与核心架构设计

### 3.1 适配器模式 (Adapter Pattern)：`TaskProgressAdapter`
将后端下发的离散遥测 DTO 规整为统一规范的 UI 呈现模型：
- **百分比修剪**：将 `filePercent` 与 `bytePercent` 统一转换为合法的 `0.0% ~ 100.0%` 数值与显示文本；
- **传输速率换算**：统一字节换算为 `B/s`、`KB/s`、`MB/s`、`GB/s`，带专属高亮前缀；
- **剩余时间友好化**：根据 `estimatedRemainingMs` 自动换算为「约 N 秒」、「约 N 分 M 秒」，避免显示生硬毫秒数；
- **智能路径修剪 (Smart Path Truncation)**：对超长绝对路径或文件路径进行前后保留提取（如 `.../workflow/runs/xxx.json`），并在 tooltip 中显示完整路径，杜绝元素撑开或截断错乱。

### 3.2 状态机模式 (State Machine Pattern)：`TaskStatePresenter`
集中统一管理任务的运行期状态、样式配色与动作守卫：
- **状态迁移与语义映射**：
  - `Idle / Unrun`：灰色稳态，动作展示「立即运行」；
  - `Running (Scanning)`：青色脉冲，展示「扫描比对中」；
  - `Running (Transferring)`：流光渐变进度条，展示「数据传输中」，动作展示「终止任务」；
  - `Running (MirrorPruning)`：琥珀色流光，展示「目标镜像清理中」；
  - `Running (Cancelling)`：红色闪烁，展示「正在安全终止...」，动作置灰禁用；
  - `AutoPaused`：琥珀色熔断告警，展示「恢复调度」；
  - `Success` / `Failed`：终态色彩与完成提示。

### 3.3 策略模式 (Strategy Pattern)：桌面主从行 vs 移动端自适应卡片
针对不同视口采用声明式渲染策略：
- **桌面端策略 (`hidden md:table-cell / md:table-row`)**：
  - **主行 (Master Row)**：固定 6 列标准比例，任务名称列保持单行紧凑；在「上次同步/状态」列显示紧凑的 `⚡ 运行中 (31.4%)` 徽章与耗时，消除折行；
  - **从属进度行 (Detail Sub-Row)**：在运行中任务的下方，插入 `<tr class="bg-cyan-950/20 border-b border-cyan-500/30"><td colspan="6">...`，全宽展开赛博流光进度卡片，使遥测数据（速率、ETA、文件计数、当前文件路径）横向舒展排布。
- **移动端策略 (`block md:hidden space-y-3`)**：
  - 将每个任务渲染为触摸友好的**赛博卡片 (Cyber Card)**；
  - 顶部：任务名称 + 运行状态标签 + 启用/禁用徽章；
  - 中部：源端与目标端路径信息（带分行层次与文件图标）；
  - 调度与策略标签栏（GFS保留、镜像删除方式、定时频率）；
  - 运行期内嵌全宽遥测卡片（流光进度条、双列指标网格、当前处理文件单行截断）；
  - 底部操作栏：触控高度 $\ge 38px$ 的弹性按钮网格，关键操作「终止任务 / 立即运行」突显。

## 4. 架构门禁约束与分层重构要求

为了严格遵守既有架构门禁：
1. **`frontend-gate.cjs` 规范**：
   - `views/BackupSyncView.js` 当前已有 1828 行，门禁上限为 2000 行。若直接将桌面从属行与移动端卡片模板混入，必将突破 2000 行上限。
   - **重构抽离方案**：抽离独立组件 `src/LinuxWebTool.WebHost/wwwroot/app/components/TaskProgressMonitor.js`（负责进度卡片与流光动效）与 `src/LinuxWebTool.WebHost/wwwroot/app/components/BackupTaskCard.js`（负责移动端独立卡片）。各组件代码行数严格控制在 $\le 300$ 行（非 views 上限 400 行），使 `BackupSyncView.js` 行数进一步精简至 1700 行左右。
2. **样式一致性**：
   - 纯原生 Tailwind CSS + `style.css`，绝不引入外部未经审核的第三方库，保证内网完全离线自包含运行；
   - 严禁使用未被 Tailwind 默认缩放支持的非标类名（如 `p-4.5`、`gap-4.5`）。
3. **性能保证**：
   - 使用 CSS 硬件加速渐变动画（`bg-gradient-to-r` 与 `transition-all`）；
   - 在移动端不渲染复杂嵌套表格 DOM，降低渲染树深度与重绘开销。

## 5. 详细开发与交付步骤

1. **创建进度渲染组件**：`TaskProgressMonitor.js`（支持 `subrow` 跨列模式与 `card` 内嵌模式）。
2. **创建移动端卡片组件**：`BackupTaskCard.js`（封装移动端单列触控卡片）。
3. **改造 `BackupSyncView.js`**：
   - 桌面端：主行精简运行状态徽章，消灭换行；从属行嵌入 `TaskProgressMonitor` 全宽呈现；
   - 移动端：引入 `block md:hidden` 卡片列表，桌面表格设置 `hidden md:block`；
   - 全面支持「增量备份任务」与「直接镜像任务」双 Tab。
4. **验证与回归测试**：
   - 运行前端架构门禁 `node src/LinuxWebTool.WebHost/wwwroot/frontend-gate.cjs`；
   - 运行全套单元测试与架构测试 `dotnet test`；
   - 执行 Release 编译。
5. **提交与推送**。
