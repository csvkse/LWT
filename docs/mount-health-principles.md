# 挂载健康检测与自动恢复原则

## 1. 检测不阻塞展示

- `/api/SystemStatus` 不得在请求线程内执行全局 `df`、无界 `stat()` 或网络文件系统探测。
- 磁盘明细读取后台缓存；缓存未就绪时返回挂载元数据与 `unknown` 状态，而不是等待真实探测完成。
- 单个挂载点异常只影响自身状态，不得造成整个磁盘列表为空。

## 2. 探测必须有边界

- 网络文件系统探针必须运行在有超时的独立子进程中；主进程不得直接对 CIFS/NFS/FUSE 调用可能卡在内核的 API。
- 探测顺序：先读 `/proc/self/mountinfo` 或 `/proc/1/mountinfo` 元数据，再做服务端口探测，最后做文件系统探针。
- 每个探测都有短超时；超时结果标记为异常或未知，不立即触发恢复。

## 3. 状态机先于恢复动作

| 证据 | 状态 | 允许动作 |
|---|---|---|
| 挂载表无记录，且配置允许自动挂载 | NotMounted | 挂锁后 mount |
| 挂载表存在，配置的 SMB 端口或远端探测失败 | ServerUnreachable | 只标记；不卸载 |
| 远端探测通过，文件系统探针连续失败 | Stale | 连续三次确认后才可恢复 |
| 恢复动作已启动 | Recovering | 同一挂载点禁止并发恢复 |
| mount/umount 失败 | RecoveryFailed | 指数退避，下次到期才重试 |
| 文件系统探针成功 | Healthy | 清零失败计数 |

## 4. 恢复必须保守且可观测

- 自动恢复只作用于应用内管理的 `Enabled` 且 `AutoMount`、未手动暂停的 SMB、WebDAV、SFTP/S3 配置。
- Stale 恢复前必须连续确认失败并重新确认远端可达；SMB 使用懒卸载，FUSE 使用正常卸载，busy 时保留挂载与缓存。
- 每个挂载点使用独立互斥锁；启动重挂、运行期健康服务和用户手动操作不得并发执行同一动作。
- 启动、周期巡检、即时检查与手动操作由统一状态机调度；启动检查不阻塞 HTTP 服务，失败后使用统一退避。
- 手动卸载设置运行期间的暂停状态；配置普通更新不解除暂停，手动挂载才解除。
- 身份冲突、凭据错误或依赖缺失等待人工处理；不得自动卸载其他来源的挂载。
- 挂载 / 卸载 / 删除前卸载失败时，操作日志必须记录后端返回的失败原因；不能只记录布尔结果。
- 恢复失败使用 `15s → 30s → 60s → 120s → 300s → 600s` 退避并加入随机抖动；成功后清零。
- 状态、最近错误、失败次数、恢复次数和下次恢复时间必须暴露给挂载 API/UI。

## 5. 未授权动作不变

- 未启用 `AutoMount` 的挂载只报告异常，不自动重挂。
- 未由应用配置管理的网络挂载只展示状态，不自动卸载或重挂。
- 服务端不因健康检查删除用户数据；恢复动作只限定在对应本地挂载点。

具体实现、任务 API 与验证限制见 [挂载状态机实施方案](mount-state-machine-plan.md)。
