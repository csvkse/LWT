# SMB 实际状态复核与访问保护实施方案

## 目标

处理“卸载超时但挂载已解除”“恢复间隙看到本地空目录”及根目录检查漏掉子目录故障。命令结果与实际状态分开记录，不改变已有任务接口，不提交或部署。

## 实施步骤

1. 挂载身份包含 mount ID、来源、类型与路径。挂载/卸载完成或超时后重新核对；卸载超时有限复核（立即、1 秒、3 秒）。旧进程未退出时暂停后续动作。
2. SMB 目录浏览与状态机共享路径锁，繁忙立即返回。读取前后核对同一个 CIFS 挂载身份，不存在或发生变化时不返回目录内容。
3. 区分超时、明确 busy 和其他命令失败，修正懒卸载提示。前端失败时不展示空目录或旧条目。
4. 每轮任务关联 ID 与日志作用域；记录阶段、结果、耗时、PID、进程状态及实际挂载身份。成功巡检 Debug，恢复和状态变化 Info，异常 Warning。
5. 可选子目录探测通过 `MountDiagnostics:ProbeSubdirectories:<配置ID>` 配置相对路径，默认关闭。限制在挂载路径内，独立进程超时验证；权限拒绝等待人工处理，不自动重挂。

## 验证边界

执行编译、前端静态检查及差异审阅。本次没有单独授权运行测试；真实 Linux/CIFS 超时、迟到进程、权限与恢复期间浏览回归仍需后续验证。应用日志不能证明内核 D 状态或 SMB 服务端故障原因。

## 已实施与使用

上述五步已写入实现。子目录选项无需数据库迁移，例如在配置中添加：

```json
{
  "MountDiagnostics": {
    "ProbeSubdirectories": {
      "d564df77-f2fe-48df-b08e-5c739ace0df2": "known-readable-folder"
    }
  }
}
```

键为真实 SMB 配置 ID，值为已知应存在的相对目录；未配置时保持原根目录与容量检查。配置加载遵循应用现有 IConfiguration 行为；不建议指定符号链接目录，因为链接目标可能不在共享内。

诊断日志关键字：`SMB command`、`SMB unmount reconciled`、`SMB mount reconciled`、`SMB probe`、`SMB blocked process`、`Mount state`、`Mount retry`。任务日志关联 ID 为 `CorrelationId`，命令与探测日志同时具有路径或配置 ID，可结合时间关联；作用域还包含 MountCorrelationId。进程状态从 `/proc/<pid>/stat` 读取，读不到时记录 exited-or-unavailable，不能据此认定内核阻塞。

现有挂载恢复可读与本轮新挂载通过验证使用不同原因文案。目录读取前后比对 mount ID、来源、类型和路径；应用内恢复动作使用共享锁。外部工具仍可能改变挂载，不能完全消除应用控制范围之外的访问竞争。

WebHost 编译（0 警告、0 错误）、修改前端文件 ESLint、前端架构门禁与差异检查通过。没有运行测试、真实 CIFS 故障回归、部署或 Git 提交。

## 启动时既有 SMB 挂载快速恢复（2026-10-03）

启动检查发现已有 SMB 挂载时，记录实际挂载身份。这只能确认“既有挂载”，不能确定它是异常退出遗留。强制删除容器配合 `/lwt:/lwt:rshared` 可能保留传播到宿主机的旧挂载。

仅对已启用自动挂载的 SMB 启动检查启用快速恢复：第一次访问超时后等待 1500 毫秒，确认旧探针已退出、挂载身份未变化，再进行一次访问验证。连续两次超时直接进入恢复，不等待常规三轮检查。复检成功则保留原挂载；权限拒绝、身份冲突和存活探针停止快速恢复。恢复前仍检查远端可达性，常规周期检查维持原策略。

卸载命令执行期间每 250 毫秒读取挂载表，不访问 SMB 文件系统。发现挂载已经解除但命令仍未结束时，结束剩余命令并最多等待一秒，再执行原有核验；只有挂载已消失且命令进程不再存活才允许重挂。挂载仍存在时保留原 30 秒命令预算，重挂之后仍需访问验证。

新增日志关键字：`SMB startup existing mount`、`SMB startup recheck`、`SMB startup fast recovery`、`SMB unmount detached early`。结合原有卸载核验、新旧挂载身份与 Healthy 日志判断是否实际恢复。

本次不改变 Docker 启动参数，不自动清理未知挂载。基础项目与 WebHost 编译、差异检查用于静态验证；真实 Linux/CIFS 故障恢复耗时与外部挂载竞争仍需现场验证。
