# 挂载状态机实施方案

## 目标与范围

统一 SMB、WebDAV、SFTP/S3 的启动恢复、周期巡检、即时检查和手动挂载任务。保留原挂载配置与健康枚举，新增管理意图、执行阶段和任务查询接口。不引入第三方状态机库，不修改宿主机 fstab，不自动清理缓存，不提交或推送本次代码。

## 架构

- `MountRuntimeModels.cs`：执行阶段、管理模式、错误类别、任务结果。
- `MountBackendCatalog.cs`：从三类配置存储重新加载配置；适配挂载状态、远端探测、本地验证和挂载/卸载。
- `MountStateMachineService.cs`：唯一自动操作后台服务。按后端与配置 ID 保存运行状态，合并检查、优先手动任务、有限并发、到期重试。
- `MountOperationCoordinator.cs`：配置 ID 锁与路径锁，更新/删除与执行共享配置锁；执行前重新加载，不使用启动旧快照。
- 各控制器：列表只读缓存；挂载/卸载提交任务，返回任务 ID；更新/删除通过配置锁协调。
- 挂载页面：显示执行阶段、暂停、下一次执行时间及结构化错误；查询手动任务最终结果。

## 状态规则

管理模式：Disabled、MonitorOnly、Automatic、ManualPaused。

执行阶段：Queued、Probing、Mounting、Verifying、Unmounting、Idle、WaitingRetry、WaitingAction。

健康状态沿用 Unknown、Healthy、NotMounted、ServerUnreachable、Stale、Recovering、RecoveryFailed、Unsupported。

1. 启动登记全部配置后提交检查；不等待全部挂载完成才开放 HTTP 服务。
2. 已挂载先核对身份，再检查实际访问；SMB 必须同时核对远端共享，冲突绝不自动卸载。
3. 远端不可达保留挂载并退避；凭据错误、冲突、依赖缺失进入 WaitingAction；配置变化或手动重试解除。
4. 本地探测连续三次失败且处于 Automatic 才恢复。SMB 可懒卸载；FUSE 正常卸载，busy 保留旧挂载与缓存。
5. 手动卸载先设置 ManualPaused，即使卸载失败也保持暂停；手动挂载解除暂停。暂停只在软件运行期有效。
6. 关闭自动挂载不卸载现有挂载。禁用配置不触发自动动作。
7. 配置更新/删除与执行共享配置锁，任务执行前重新加载；旧版本任务取消。路径修改必须先卸载，防止留下旧挂载。
8. 健康快照在串行控制区内更新，避免并发检查丢失失败计数。

## 调度边界

默认工作并发 3（`MountScheduler:Concurrency`，可配置 1–16）；同配置和同路径不并发。检查请求合并，手动任务优先；等待重试不占工作槽与路径锁。每项按完成时间安排下次检查，健康默认 30 秒加抖动，恢复失败使用 15/30/60/120/300/600 秒加抖动。已挂载 FUSE 的远端绕过缓存探测间隔为 5 分钟，恢复前再次探测。SFTP/S3 收到首个目录项即结束探测，空目录要求正常退出；后端可能预先读取目录，不能保证只发出一次请求。单次任务总预算默认 120 秒（`MountScheduler:TaskTimeoutSeconds`，可配置 10–600），底层网络与子进程仍有独立超时。

取消不是恢复失败。子进程可能卡在内核，超时不能证明动作已停止；记录尚未退出的探针，后续不重复创建同路径探针。重试前重新检查实际挂载记录。

## API 与兼容边界

挂载、卸载和删除保留原路由，但返回 `202` 与 `MountTaskInfo`。客户端须按任务 ID 查询 `GET /api/MountTasks/{id}`，以 `Completed`、`Success` 判断最终结果，不能把提交成功当作动作成功。挂载页面已接入轮询。任务与手动暂停状态仅在服务运行期间保存，重启后不保留；已完成任务最多保留 256 项、30 分钟。

移除各后端原有启动与健康后台循环。旧 `MountHealthService` 仅保留显式检查与既有测试兼容能力，不再注册为后台服务；原健康枚举值与配置结构保持兼容。

## 验收与验证约束

重点场景：旧配置不执行、手动暂停不恢复、错误共享不卸载、慢条目不拖住其他路径、远端故障保留挂载、连续失败只恢复一次、FUSE busy 不强卸载、软件停止不启动新任务。
